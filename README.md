# 배달의민족 외식배달비 자동조사

**Python · Jupyter Notebook · BlueStacks 5 · uiautomator2 · openpyxl**

기존 Excel 조사표에 등록된 대상처를 배달의민족 앱에서 조회해 배달비, 최소주문금액, 사업자정보, 메뉴를 수집하고 이전 조사자료와 비교하여 기록하는 자동화 프로젝트입니다. 핵심 조사 함수는 재사용 가능한 Python 모듈로 정리하고, 실제 조사는 짧은 Jupyter Notebook에서 **조사 월·파일 경로·조사 대상**만 지정하도록 구성했습니다.

## 개발 배경

수작업 외식배달비 조사에는 지역별 배달 주소 설정, 기존 대상처와 메뉴 찾기, 여러 배달유형의 요금 확인, 사업자정보 비교, Excel 입력 등의 반복 작업이 필요합니다. 동시에 검색 결과가 불확실하거나 앱 조작에 실패한 경우에는 잘못된 결과를 자동 확정하지 않아야 합니다.

이 프로젝트는 **반복적인 수집 작업은 자동화하되, 불확실한 판단은 사람에게 넘기는 구조**를 목표로 개발되었습니다.

| 분야 | 제공 기능 |

| 조사 환경 | BlueStacks에서 배달의민족 연결, 주소 설정, 조합별 BlueStacks 재시작 |
| 정보 수집 | 대상처 검색, 배달유형별 최소주문금액과 요금, 사업자명·대표자명·주소, 기존 메뉴 확인 |
| 후보 검토 | 동일 대상처 후보, 유사 메뉴 추천, 신규 대상처 후보 탐색 |

### 조사 상태를 구분하는 이유

검색 결과에 여러 후보가 나오거나 앱 연결이 실패했다고 해서 업체가 존재하지 않는 것은 아닙니다. 기존 코드의 `FOUND`, `MULTIPLE_MATCH_REVIEW`, `SAME_STORE_REVIEW`, `REPLACEMENT_NEEDED`, `TECHNICAL_FAIL` 등은 서로 다른 상황으로 취급합니다. 사람 확인이 필요한 항목은 조사로그에 남깁니다.

## Windows에서 실행하기

1. **Python/Jupyter**, **BlueStacks 5 Pie64**, 배달의민족 앱을 준비하고 BlueStacks에서 ADB(안드로이드 디버그 브리지) 기능을 켠 상태로 인스턴스를 실행합니다. 원본은 Windows `C:\Program Files\BlueStacks_nxt` 설치 구조를 사용합니다.
2. 저장소를 내려받거나 기존 로컬 저장소에서 `git pull`로 최신 코드를 받습니다.
3. 프로젝트 폴더의 명령 프롬프트에서 Python 라이브러리를 설치합니다.

   ```cmd
   python -m pip install -r requirements.txt
   ```

4. `run_survey_template.ipynb`를 복사해서 같은 폴더에 `run_survey.ipynb`를 만들고, Jupyter에서 복사본을 엽니다.
5. 안내 Markdown 아래 **설정 셀 한 곳**을 수정합니다. 마지막 셀만 실행합니다.
6. 처음에는 `PREVIEW_ONLY = True`로 실행해 Excel 대상 건수와 실제 저장 경로를 점검합니다. 실조사 준비가 되면 `False`로 바꿔 실행합니다.

**BlueStacks ADB 자동 연결:** `PREVIEW_ONLY=False`로 실행하면 `baemin_survey.py`의 `_connect()`가 설정한 `BLUESTACKS_DIR` 안에서 `HD-Adb.exe`를 확인한 뒤 `start-server`, `devices`를 자동 실행하고, 확인된 **유일한** 기기에 `uiautomator2`로 연결합니다. 터미널 명령을 매번 직접 실행할 필요는 없습니다. ADB에 기기가 없거나 여러 개면 추측해서 연결하지 않고 오류를 알려 줍니다. 이때 BlueStacks 실행 상태와 ADB 활성화 여부를 확인하세요. 연결 실패 시 결과 Excel 생성 전 중단합니다. **이 자동 연결 변경은 모의 테스트만 완료했으며 Windows 실제 BlueStacks에서는 아직 검증 전입니다.**

### 설정 예시

```python
from baemin_survey import run_survey

MONTH = 10
INPUT_FILE = r"C:\조사자료\원본.xlsx"
OUTPUT_FILE = r"C:\조사자료\10월_조사결과.xlsx"
MODE = "행"
TARGET = [486]
NEW_SURVEY = False
PREVIEW_ONLY = True
BLUESTACKS_DIR = r"C:\Program Files\BlueStacks_nxt"
```

**실행 셀**

```python
run_survey(
    month=MONTH, input_file=INPUT_FILE, output_file=OUTPUT_FILE,
    mode=MODE, target=TARGET, new_survey=NEW_SURVEY,
    bluestacks_dir=BLUESTACKS_DIR, preview_only=PREVIEW_ONLY
)
```

`MODE`와 `TARGET` 값만 교체하여 다음 조사를 선택할 수 있습니다.

| 조사 종류 | `MODE` | `TARGET` 예시 |
|---|---|---|
| 특정 Excel 행 | `"행"` | `[486]` |
| 여러 Excel 행 | `"행"` | `[486, 487]` |
| 대상처 이름 정확히 일치 | `"대상처"` | `"가게명"` |
| 특정 조사 주소 | `"주소"` | `"엑셀 H열에 적힌 정확한 주소"` |
| 특정 지역 | `"지역"` | `"대전"` |
| 복수 지역 | `"여러지역"` | `["대전", "세종"]` |
| 기존 조합 | `"조합"` | `[2, 4]` |
| 전국 전체 | `"전체"` | `None` |

대상처 이름이 중복되면 자동 확정하지 않고 Excel 행 번호를 요청합니다. 주소는 조사표 H열 값과 **정확히 일치**해야 합니다.

## Excel 입출력

원본 조사 시트는 `조사자료(rawdata)`이고, 대상처는 8행부터 시작합니다.

| Excel 열 | 내용 |
|---|---|
| D | 업종 |
| E | 조사 품목 |
| F | 지역 |
| H | 조사 기준 주소 |
| I | 기존 대상처명 |
| J | 대표자명 |
| K | 사업자주소 |
| L | 기존 메뉴 |

월별 배달정보 및 변동사항 열은 기존 `get_month_cols()`와 `get_result_cols()`의 계산을 **변경하지 않았습니다**. 조사 결과는 `조사자료(rawdata)`와 `조사로그`에 기록됩니다.

- **행·대상처·주소·지역·복수 지역:** 기본적으로 `OUTPUT_FILE`에 저장합니다. 단, 행/대상처 재조사 시 `OUTPUT_FILE`과 같은 이름에서 `_자동전체조사.xlsx`를 붙인 파일이 이미 있다면 그 전체조사 결과에 기록합니다.
- **조합·전체:** 기존 코드와 동일하게 `OUTPUT_FILE` 이름 뒤에 `_자동전체조사.xlsx`를 붙인 파일에 저장하고 `자동조사진행` 시트로 완료 주소지를 관리합니다. 예: `10월_조사결과_자동전체조사.xlsx`.
- **`NEW_SURVEY = False`:** 기존 결과가 있으면 이어서 사용합니다.
- **`NEW_SURVEY = True`:** 기존 결과 초기화를 의도한 경우에만 사용합니다. 기존 결과가 있으면 확인 입력을 요구하고 백업합니다.

## 기술적 제약과 안전 수칙

- **현재 간편 실행 함수는 9~12월만 허용합니다.** 원본 조사표의 8월 이후 열 배치에 맞춘 수식이므로 1~8월을 임의 실행하면 잘못된 열을 덮어쓸 수 있어 제한했습니다. 해당 월을 사용하기 전에 실제 Excel 양식의 열 매핑을 확인해야 합니다.
- **조합·전체 조사는 원본의 745개 대상처 구성만 허용합니다.** 다른 건수의 Excel에서는 지역/행/주소 모드를 이용하세요.
- 부분 조사는 주소지별 저장을 수행하지만, 전체/조합 모드의 `자동조사진행` 완료 주소지 자동 건너뛰기와는 별개의 실행 방식입니다.
- 새 모듈의 BlueStacks 연결 및 실제 조사 745건 통합 실행은 **아직 검증하지 않았습니다**. 반드시 `PREVIEW_ONLY=True` 확인 후 테스트용 Excel과 소수 행으로 기능을 점검하세요.
- 앱의 UI나 BlueStacks/ADB 실행 환경이 바뀌면 uiautomator2 조작이 실패할 수 있습니다. 기술적 실패를 대상처 부재로 해석하지 않습니다.
- 실제 조사 Excel, 업체·대표자 정보, 로컬 경로와 저장된 실행 출력이 있는 노트북은 공개 저장소에 추가하지 마세요. `.gitignore`가 있더라도 커밋 전 파일 목록을 직접 확인하세요.
