# 배달의민족 외식배달비 자동조사

**Python 기반 배달의민족 외식배달비 자동 수집 및 조사자료 관리 시스템**

## 1. 프로젝트 소개

본 프로젝트는 기존 Excel 조사표를 기반으로 배달의민족 앱에서 외식배달비 관련 정보를 자동으로 수집하고, 이전 조사자료와 비교하여 결과를 기록하는 자동화 시스템입니다.

Python과 BlueStacks Android 에뮬레이터를 연동하여 대상처 검색부터 배달정보 수집, 변경사항 비교, 조사로그 관리까지 수행합니다.

단순 데이터 수집을 넘어 **자동으로 처리할 수 있는 정보와 사람이 직접 확인해야 하는 정보를 구분**하도록 설계했습니다.

## 2. 개발 배경 및 목적

외식배달비 조사는 지역별 조사 주소를 설정하고, 기존 조사 대상처의 영업 여부와 배달정보 등을 반복적으로 확인해야 하는 작업입니다.

수작업 조사에는 다음과 같은 어려움이 있습니다.

- 대상처별 반복적인 주소 설정 및 검색
- 가게배달·알뜰배달·한집배달 요금 확인
- 기존 대상처 및 메뉴의 변경 여부 확인
- 이전 조사자료와 현재 조사자료의 비교
- 조사 결과 입력 및 검토 대상 관리
- 대량 조사 시 발생하는 시간적 부담

이를 해결하기 위해 기존 Excel 조사표의 구조를 유지하면서 반복적인 조사 과정을 자동화했습니다.

## 4. 시스템 처리 흐름

1. **Excel 조사표 로딩** — 조사 월, 지역, 주소지 및 대상처 정보 불러오기
2. **조사 환경 연결** — ADB를 통해 BlueStacks의 배달의민족 앱 연결
3. **조사 주소 설정** — 대상처가 속한 조사 기준 주소로 변경
4. **대상처 검색** — 기존 대상처 검색 및 결과 비교
5. **정보 수집** — 배달정보, 사업자정보 및 메뉴 확인
6. **변경사항 비교** — 이전 조사자료와 신규 수집자료 비교
7. **결과 분류** — 자동 처리 가능한 항목과 사람 확인 대상 구분
8. **Excel 기록** — 조사표와 조사로그에 결과 저장
9. **검토 및 재조사** — 필요 시 검토 대상 확인 및 지정 재조사

### 조사 결과 분류

검색 결과가 불확실하거나 기술적 문제가 발생한 경우, 임의로 대상처를 확정하지 않고 별도의 상태로 분류합니다.

대표적인 상태 코드는 다음과 같습니다.

- `FOUND`: 대상처 검색 및 진입 성공
- `MULTIPLE_MATCH_REVIEW`: 복수 검색 후보 검토 필요
- `SAME_STORE_REVIEW`: 동일 대상처 여부 확인 필요
- `REPLACEMENT_NEEDED`: 신규 대상처 탐색 필요
- `TECHNICAL_FAIL`: 검색 또는 화면 조작 과정의 기술적 실패

기술적 실패를 대상처 부재로 처리하지 않는 것을 핵심 설계 원칙으로 적용했습니다.

## 6. 설치 및 실행 방법

### 실행 전 준비

- Python 및 Jupyter Notebook 사용 환경
- BlueStacks 5와 배달의민족 앱
- ADB 연결 환경
- 지정된 Excel 조사표 형식의 입력 자료

### Python 라이브러리 설치

프로젝트 폴더에서 다음 명령어를 실행합니다.

`python -m pip install -r requirements.txt`

BlueStacks와 ADB는 Python 패키지와 별도로 준비해야 합니다.

### 조사 설정

Jupyter Notebook의 `1. 조사 설정`에서 다음 항목을 지정합니다.

- `SURVEY_MONTH`: 조사 대상 월
- `FILE`: 입력 조사표 경로
- `OUTPUT_FILE`: 조사 결과 파일 경로
- `NEW_SURVEY`: 새 조사 시작 여부

입력 조사표는 기존 조사 시스템에서 사용하는 열과 시트 구조를 갖추고 있어야 합니다.

### 조사 실행

1. Notebook의 조사 설정 및 초기화 셀 실행
2. BlueStacks와 ADB 연결 확인
3. 조사 관련 함수 정의 셀 실행
4. `5-3` 전체조사 또는 `5-4` 선택 지역 조사 중 필요한 실행 방식 선택
5. 조사 종료 후 결과 및 조사로그 확인
6. 필요 시 `6-2` 지정 대상처 재조사 및 `6-3` 저장

**주의:** 전체조사 셀은 기존 조사표의 745개 대상처 구성을 기준으로 작성되었습니다. 임의의 데이터로 전체조사를 실행하려면 조사 대상 구성과 실행 조건을 먼저 확인해야 합니다.

또한 Notebook에는 실제 조사를 시작하는 셀이 포함되어 있으므로 전체 셀을 한 번에 실행하는 방식은 권장하지 않습니다.

## 7. 입력 및 출력 데이터

### 입력 데이터

기본 시트: `조사자료(rawdata)`

조사에 사용하는 주요 정보는 다음과 같습니다.

| Excel 열 | 내용 |
|---|---|
| D | 업종 |
| E | 조사 품목 |
| F | 지역 |
| H | 조사 기준 주소 |
| I | 대상처명 |
| J | 대표자명 |
| K | 사업자주소 |
| L | 기존 조사 메뉴 |

조사 대상 데이터는 8행부터 읽으며, 조사 월에 따라 배달정보 및 결과 기록 열이 달라집니다.

### 출력 데이터

- 기존 조사표 구조에 현재 조사 결과 기록
- `조사로그` 시트에 대상처별 조사 상태 및 검토 사유 기록
- `자동조사진행` 시트에 완료된 주소지 및 진행 상태 기록
- 전체조사 시 별도의 `*_자동전체조사.xlsx` 결과 파일 생성

실제 업체 및 대표자 관련 정보가 포함된 원자료와 조사 결과 파일은 저장소에 공개하지 않습니다.

## 8. 자동조사 성과

전국 17개 지역의 745개 대상처를 대상으로 전체 자동조사를 수행했습니다.

| 항목 | 결과 |
|---|---|
| 전체 조사 대상 | 745개 |
| 전체 처리 건수 | 745개 |
| 조사 그룹 | 6개 |
| 조사 지역 | 전국 17개 지역 |
| 최종 조사 시간 | 213.6분 |
| 이전 조사 시간 | 약 315분 |
| 조사 시간 단축률 | 약 32.2% |
| BlueStacks 자동 재시작 | 5회 |

기존 약 5시간 15분이 소요되던 조사 작업을 약 3시간 34분으로 단축했습니다.

전체 처리 건수에는 자동 확정뿐 아니라 사람의 확인이 필요한 사례도 포함됩니다. 따라서 745건 전체 처리와 745건 자동 확정은 구분해야 합니다.

## 9. 기술적 한계 및 유의사항

- 배달의민족 앱 화면 구조가 변경되면 일부 자동화 함수의 수정이 필요할 수 있습니다.
- 대상처 검색 결과가 불확실한 경우 자동 확정을 보류합니다.
- 기존 메뉴가 없거나 유사 메뉴만 발견된 경우 사람의 검토가 필요할 수 있습니다.
- 화면 조작 또는 앱 연결 실패는 대상처가 실제로 없다는 의미가 아닙니다.
- 기존 Excel 조사표 형식과 BlueStacks 실행 환경에 의존합니다.
- 현재 코드는 검증된 조사 환경을 중심으로 구성되어 있으며 범용적인 모든 Android 환경에서의 실행을 보장하지 않습니다.
